# ADR-001: 정적 HTML/CSS + GitHub Pages + Playwright PDF Export

- 상태: 채택 (2026-11-13)
- 목적: SK AIGEN 지원용 **페이지형 포트폴리오를 한 소스에서 웹 공개와 PDF 제출로 제공**

## 해결하려는 문제

평가자는 포트폴리오를 빠르게 열람해야 하며, 지원자는 PDF의 글꼴·레이아웃·페이지 분리가 안정적이어야 한다. 수정 이력도 GitHub에서 관리해야 한다. 현재 필요한 것은 읽기 전용 포트폴리오이며 로그인·서버 API·DB는 없다.

## 검토한 대안

| 후보 | 장점 | 현재 목표에서 불리한 점 |
| --- | --- | --- |
| Next.js + Vercel | 서버 기능·동적 라우팅·확장성 | 정적인 제출 문서에 빌드/런타임이 과함 |
| PPTX/Figma → PDF | 슬라이드 단위로 편집하기 편함 | 웹과 PDF의 단일 원본 및 코드 변경 추적에 불리함 |
| Markdown → PDF | 내용 중심 관리가 쉬움 | 정교한 표지 구성 및 페이지별 레이아웃 제어에 한계 |
| **정적 HTML/CSS + GitHub Pages + Playwright** | **경량 배포, GitHub 이력, print CSS로 PDF와 웹의 동일 소스** | 브라우저 화면과 인쇄 환경을 함께 테스트해야 함 |

## 결정

**정적 HTML/CSS**로 페이지를 디자인하고, **GitHub Pages**로 공개하며, **Playwright/Chromium**으로 인쇄용 PDF를 생성한다. 제출 결과물은 스크린샷 묶음이 아니라 텍스트를 선택하고 검색할 수 있는 PDF이다.

## 선정 근거

1. **목표 적합성**: 평가자가 읽는 문서에 서버 기능은 본질적이지 않다.
2. **검증 가능성**: 웹과 PDF를 같은 `site/` 소스에서 생성한다.
3. **변경 추적**: GitHub 커밋으로 내용·디자인 변경 이력을 관리한다.
4. **비용**: 정적 파일만 배포하며 서버 비용을 줄인다.
5. **확장성**: A4 규격의 `article.page`를 여러 장 쌓고 필요 시 다른 도구로 변경을 재평가한다.

## 트레이드오프와 보완

- 자동 페이지 나눔 대신 페이지 크기 고정으로 디자인한다.
- 수정할 때마다 화면과 PDF를 모두 확인하고 한글 글꼴·넘침·중복 페이지를 검사한다.
- 프로젝트 성과·기여도·수치는 근거 문서를 확인하기 전까지 확정적으로 기술하지 않는다.
